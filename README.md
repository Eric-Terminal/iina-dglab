# IINA 郊狼音频联动

[English](README.en.md)

将 IINA 当前播放音频的响度、起音变化与过零率映射为郊狼波形，通过 **DG-LAB 4 App 的 Socket 控制（V4）**或 **Mac 蓝牙直连**输出。插件有独立控制窗口、实时电平图、A/B 独立限幅和停止按钮，支持简体中文与英文。

目标环境：带插件系统和 `standaloneWindow.isOpen()` 接口的 IINA（已在 1.5.1 测试）与郊狼 3.0。直连要求 macOS 12+，支持 Intel 与 Apple Silicon；App 模式要求 DG-LAB 4。缺少窗口状态接口时会禁用开始按钮并提示升级。当前不支持旧 App 的 V3 Socket 协议，也不控制郊狼 2.0 或其他型号。

## 安装与连接

1. 从 [Releases](https://github.com/Eric-Terminal/iina-dglab/releases/latest) 下载 `.iinaplgz` 安装包，双击后在 IINA 中完成安装并启用。也可在 IINA 的插件设置中通过 GitHub 仓库地址 `https://github.com/Eric-Terminal/iina-dglab` 安装。若没有出现插件菜单，重启 IINA。
2. 打开带音轨的媒体，在该播放窗口的 **插件 → 郊狼音频联动 → 打开音频联动（使用当前窗口）** 打开控制台。多个播放窗口中，只有最后手动选择的窗口提供音频。
3. 点 **连接 App**。默认「远程服务器」使用官方 V4 中继 `wss://trex.dungeon-lab.cn/v4`，也可在「连接设置」填写自建 V4 地址；无需本机 Node.js。插件会记住手动选择的连接方式。
4. 在 DG-LAB 4 的 **Socket 控制 → 连接服务器**中配对：手机可扫二维码，同机 App 可粘贴插件显示的完整 Socket 地址。
5. 在 App 中连接并启用郊狼 3.0；插件会自动接收设备列表、连接状态及通道上限。有多个设备时手动选择一个。
6. 首次使用时，为需要的通道设置强度上限，点 **应用参数**，再点 **开始联动**。运行中修改门限等参数后，点 **应用参数** 会清理旧任务并继续联动，无需再次点击开始。若联动已停止且仍有未应用的修改，开始按钮显示「请先应用参数」；点击停止不会丢弃修改。两个通道的初始上限均为 **0**；仅连接、配对和预览不会产生波形输出。

右上角「语言」可以选择跟随系统、简体中文或 English。自动模式将中文系统语言映射为简体中文，其他语言使用英文。选择会保存；切换语言不重连设备、不更改参数或联动开关。

### 蓝牙直连，无需官方 App

1. 断开官方 App 对设备的蓝牙连接，给郊狼 3.0 开机。IINA 不需要通过 PlayCover 运行 App。
2. 在插件中选择 **蓝牙直连 · 无需 App**，点 **扫描设备**。首次使用时，允许「郊狼蓝牙助手 / Coyote Bluetooth」访问蓝牙；若曾拒绝，可在系统设置的隐私与安全性 → 蓝牙中开启。
3. 选择附近的设备，点 **连接设备**。助手先把硬件软上限设为零，写入零强度和零波形，等设备确认后再应用插件的上限。显示「蓝牙已连接」后仍需手动点「开始联动」。
4. 设置通道上限并应用参数，再开启联动。默认上限为零；重新连接不会自动恢复输出。

直连使用安装包内的原生 Swift/CoreBluetooth 助手，不需要 Node.js、Xcode 或中继服务器。助手只在本机随机回环端口与 IINA 通信，连接令牌不发送到 WebView 或网络服务器；断开、关闭控制台或失去租约后退出。

「直连设备校准」中的频率平衡、脉宽平衡范围均为 0～255，默认 0，两通道共用。它们与通道软上限通过官方 BF 指令写入，**设备会断电保存这些设置**；不会读取或继承 App 的校准。初次连接和应用参数会改写这些值，返回 App 使用时请在那里核对自己的设置。

当前助手为 ad-hoc 签名，尚无 Apple Developer ID 签名或公证。下载后 macOS 可能阻止首次启动；只在确认安装包来源后，通过系统设置 → 隐私与安全性批准该助手，或从源码构建。插件不会自动关闭系统安全检查。

蓝牙封包、原生进程与界面流程已自动验证，**实体设备的发现、握手、输出和停止时序尚待实机验证**。保留默认的远程 App 模式供选择。

插件里的强度上限与波形幅度是两个不同概念：通道强度取用户上限与 App 上限的较小值；音频控制的是波形幅度（0～100）。不要将波形幅度 100 理解为设备强度 100。

「开始联动」是自动跟随开关，可以在视频暂停或等待音频时先开启。暂停、静音、门限以下或采样暂时中断时会归零并保持开启；收到新的有效音频后自动继续，不必再次点击开始。

### 波形提前量

在「映射与通道」中设置 **波形提前量**，范围 **0～1000 ms**，默认 **0**。例如填写 `100` 后点击「应用参数」，插件会使用当前声音 **100 ms 之后**的音频特征生成波形。正数表示提前输出，适合自行补偿传输与感知延迟；应用后仍保持原来的联动开关状态。

当前音源的 RMS、峰值、过零率、曲线和波形预览始终使用**当前播放时刻**的音频，不跟随提前量移动；只有设备输出使用提前读取的音频。两者有独立的映射历史与平滑状态，可用预览作为校准参照。1.2.0 的预览与输出共用了提前读数，1.3.0 已拆开。

插件按音频时间戳从 mpv 已解码的预读数据中选帧，不改动 `audio-delay` 或音画偏移。非零提前量会按需扩大当前播放器的音频缓冲；设回 0、播放结束或关闭控制台时恢复原配置。较大的缓冲可能增加定位、倍速切换和音频滤镜调整后的等待时间。倍速播放仍按真实毫秒补偿，例如 2 倍速下的 100 ms 对应媒体时间轴前方 200 ms。

提前量不是端到端延迟测量。100 ms 的发送周期、音频帧边界、映射平滑、网络、App 与蓝牙仍有误差或抖动，需要自行微调。开始播放、定位、媒体末尾或直播缓冲不足时，未来音频可能尚未存在；这时停止输出并等待可用数据，不用旧帧代替，也不预测声音。

### 可选的本机中继

如果官方 App 与 IINA 在**同一台 Mac**，可以选择「本机中继」。它由插件自动启动，需要 Node.js 22+；自动查找 `/opt/homebrew/bin/node` 和 `/usr/local/bin/node`，也可在连接设置中填写其他绝对路径。复制完整 Socket 地址到同机 App 即可尝试连接，无需手动启动终端服务。

本机模式仅监听 `127.0.0.1`，不会访问官方中继、生成 `.cn` 跳转二维码或开放局域网端口。每次启动使用随机端口和临时连接密钥，重新连接后需粘贴新地址。关闭控制台、断开连接或退出 IINA 后，中继会退出；插件中断时原生租约在约 8～9 秒内到期。租约管理进程存活，设备任务仍使用下文所述的 100/250 ms 时限。

1.1.0 在 PlayCover 运行的 DG-LAB 4.2.6 中出现过握手 HTTP 403，日志确认 TCP 已连接本机端口。1.1.1 改为在路径中携带密钥，并接受配对地址的尾斜杠，以兼容地址规范化；究竟是哪个字段被客户端改写，日志尚无法确定，修订后的真实 App 兼容性仍待验证。遇到本机连接问题时可使用默认远程模式。

### 没有音频读数时

从**正在播放的窗口**的插件菜单选择「打开音频联动（使用当前窗口）」。1.1.0 从该窗口直接启用采样，并在播放器重建滤镜链后恢复统计滤镜。当前音源旁会显示具体状态：暂停、静音、缓冲、没有可用 PCM 或滤镜挂载失败。只有有效的实时统计才显示 RMS、峰值和过零率；单独连接 App 不会产生音频读数。

从旧版更新后请重启 IINA，让主入口和全局入口同时加载新版。若仍无读数，可从「插件 → 开发者工具 → 郊狼音频联动」（不带 Global）检查 `iina.mpv.getNative('af')` 是否包含 `iina_dglab`，以及播放时的 `iina.mpv.getNative('af-metadata/iina_dglab')`。这些诊断只读，不会开始设备输出。

## 算法

mpv 的 `astats` 统计每个解码帧，`ametadata` 将统计值及时间戳写入插件临时文件。插件每 100 ms 增量读取，根据 `audio-pts + 提前量 × 播放倍速` 选择对应帧，不直接把解码预读的最后一帧当作当前声音。临时文件不包含原始音频或媒体文件名；达到约 32 MiB 时轮换，关闭控制台、播放结束或窗口退出时删除，内存只保留有限帧。

不捕获麦克风或系统音频。统计滤镜只追加自己的标签 `iina_dglab`，不会覆盖均衡器或其他已有滤镜。音频直通不提供可用 PCM 统计，需要在 IINA 中关闭直通。

默认「动态混合」使用 RMS 为主的电平，并在 RMS 快速上升时增加 Peak 权重：

```text
起音变化 = max(本次 RMS − 上次 RMS, 0)
峰值权重 = 0.15 + 0.30 × clamp(起音变化 / 12, 0, 1)
混合电平 = RMS + max(Peak − RMS, 0) × 峰值权重
归一化响度 = clamp((混合电平 − 当前门限) / (满幅电平 − 当前门限), 0, 1)
目标波形幅度 = floor(归一化响度 ^ 响应指数 × 波形幅度上限)
```

- **自适应门限**：取最近约 8 秒电平的第 20 百分位作为底噪估计，加 6 dB 余量。至少 20 个样本后启用，门限每秒最多变化 3 dB，最多比用户门限高 12 dB，并限制在满幅电平以下。
- **滞回**：开门需要超过当前门限 2 dB，关门使用当前门限，减少临界电平反复开关。低于关闭门限立即清零，不做静音拖尾。
- **包络平滑**：门限以上使用 35 ms attack / 90 ms release 的指数平滑。默认响应指数为 1.1；可选择纯 RMS 或 Peak，或调整响应指数。
- **频率映射**：读取每个音频声道的 `Zero_crossings_rate`，按 RMS 能量加权，换算到 48 kHz 标度，再做三点中值和 120 ms 指数平滑。ZCR 从 0.02 升到 0.22 时，频率编码从 100 降到 10。编码不是 Hz，越小表示脉冲越密。
- **波形封包**：每帧 8 字节，前 4 字节为频率编码，后 4 字节为幅度的 70%、85%、100%、90%。单帧代表 100 ms。

ZCR 与响度不能可靠识别人声、撞击或音乐；自适应门限也不能分离背景音乐。持续音乐或持续人声都可能使门限上升，此时可以关闭自适应门限并手动调整。这里没有生理恢复、避免麻木等效果保证。

`astats reset=1` 只是每个解码音频帧重置统计，不代表零延迟。时间戳选帧消除了直接读取末帧造成的不确定预读偏移，仍受音频驱动时钟精度影响；很短的瞬态也可能落在两次采样之间。

## 停止与恢复

| 情况 | 行为 |
| --- | --- |
| 暂停、静音、音量为零、缓冲、跳转、低于门限 | 清除本插件使用通道的任务并将强度归零，保持联动开关；恢复有效音频后继续 |
| 运行中应用新参数 | 清理旧参数下的任务，保留联动开关；清理成功且有有效音频后按新参数继续 |
| 采样中断超过 350 ms | 丢弃过期读数、清除输出，保留开关并等待新音频；恢复后自动继续，不补发旧帧 |
| 播放结束、换文件、换音源、换设备、断连、指令失败 | 停止并解除联动，必须手动重新开始 |
| 点击停止、控制台内按 Esc | 停止并解除联动 |
| 播放窗口中按 Ctrl+Option+Esc | 通过插件菜单快捷键停止 |
| 关闭控制台 | 原生定时器检测并停止、断开连接，清理统计文件及恢复音频缓冲；关闭本机中继或蓝牙助手 |

App 模式每次只发送当前的一帧，使用 V4 的 `im: true` 替换同类任务。未收到上一批指令的响应时丢弃新帧，不排队补发；波形任务最长 100 ms，临时强度任务 250 ms。停止时清任务并发送归零命令。网络已断开时无法保证停止指令送达，有限时任务用于限制残留输出；硬件实际停止时间仍需实机验证。

蓝牙模式每 100 ms 发送一条官方 B0 双通道指令，助手只保留最新帧且每帧只消费一次。缓存波形 100 ms 后失效，临时强度 250 ms 后失效；没有有效帧时发送零波形。强度修改等待对应 B1 序号确认，500 ms 未确认则尝试归零并断开。缓存时限不等于精确的物理停止时刻：帧写入、设备消费和蓝牙传输仍有延迟。助手租约为 8 秒，租约只管理进程存活，不延长波形缓存。

设备指令的确认等待为 2 秒，与上述任务时限独立。确认慢时暂停发送新帧，不延长或补发旧任务。若失败，控制台保留最初错误、通道和指令名称；「App 已连接」只表示配对链路仍在，不代表每条设备指令都得到确认。停止未确认时需断开重连。

App 未回传通道上限、通道静音或设备离线时，不开始该通道输出。恢复连接不会自动开始。不要同时使用其他控制端给同一设备通道安排任务，清理操作按设备与通道生效。

## 连接与权限

连接采用控制窗口的标准 WebSocket 与官方 `dglab-kit`，而非 `iina.ws`：IINA 原生 `ws` 是服务端接口，其当前实现既不暴露请求 URL，又发送二进制帧。插件使用一个全局控制窗口管理连接，各播放器只传递本地统计值。

本机模式下，插件与同机 App 的控制通信仅经过回环地址。远程模式下，中继接收设备操作与 App 状态；插件不上传媒体文件、文件名、原始音频或 RMS/ZCR 数据。官方 App 自身的其他联网行为由 App 决定。

安装时声明的权限：网络用于 Socket 通信、本机中继租约和蓝牙助手的回环通信；文件系统用于管理临时音频统计、执行 `af` 命令、调整预读缓冲，以及启动插件内的中继或蓝牙助手。蓝牙权限仅在主动扫描时由助手申请。插件不会扫描用户媒体目录。运行依赖已经打包，安装插件无需 npm；只有可选本机中继模式需要另行安装 Node.js。

## 开发与验证

需要 Node.js 22+。构建蓝牙助手需要 macOS 与提供 Swift 编译器的 Xcode Command Line Tools；脚本为 macOS 12+ 编译 Intel/Apple Silicon 通用二进制并 ad-hoc 签名。打包使用系统自带的 `zip` / `unzip`。

```sh
git clone https://github.com/Eric-Terminal/iina-dglab.git
cd iina-dglab
npm ci
npm run check
npm run build:native
npm test
npm run test:native # 纯协议测试，不访问蓝牙
npm run test:mpv   # 需要本机 ffmpeg 和 mpv；使用空音频输出，不连接设备
npm run test:timing # 合成音画验证 0 / 100 / 1000 ms、倍速与跳转
npm run pack
```

如果项目路径包含 `:`，npm 注入的 `.bin` 路径会被 POSIX PATH 分隔。因此脚本显式通过 `node node_modules/...` 调用工具，避免意外使用系统全局版本。

`dist/` 随 Git 提交，IINA 无需现场构建。开发时可以运行官方 CLI：

```sh
/Applications/IINA.app/Contents/MacOS/iina-plugin link "$PWD"
```

重启 IINA 并在插件设置中启用开发插件。

`scripts/preview.ts` 提供仅监听回环地址的本地界面测试页，包含合成音频与虚拟设备：

```sh
npm run build
node node_modules/tsx/dist/cli.mjs scripts/preview.ts
```

自动测试覆盖声学映射、持续联动、参数应用、独立预览、英文文案、完整控制台流程、时间戳选帧、提前量、缓冲恢复、IINA 入口，以及官方 SDK 经真实 WebSocket 的 V4 往返与慢响应。本机中继和蓝牙助手有回环鉴权、独立进程启动、租约退出测试；Swift 协议测试覆盖 BF/B0/B1、限幅、归零、序号确认、过期帧与非法输入。这些测试不扫描或连接蓝牙硬件。

真实 mpv / FFmpeg 测试验证静音、180 Hz 与 5 kHz 音频元数据及滤镜保留；合成音画验证运行中设置 0 / 100 / 1000 ms 的提前量、2 倍速、暂停、向后跳转、特殊字符路径及缓冲恢复，使用空输出，不连接设备。

用户已在 IINA 1.5.1 / mpv 0.41.0 确认此前版本的音频曲线、暂停状态以及官方中继配对与设备回传。提前量仍需在实际音频设备中校准；本机中继修订后的真实 App 连接、蓝牙直连和实体设备停止时序尚未完成实机验证。「App 已连接」时发生过停止未确认，截图不能确定原始失败原因；1.3.0 增加了命令诊断并放宽确认等待，尚不能声称已解决该实机问题。

发布新版本时，同步更新 `Info.json` 和 `package.json` 中的版本号，递增 `Info.json` 的 `ghVersion`，重建并提交 `dist/`，然后创建版本标签和附带安装包的 GitHub Release。IINA 使用仓库信息与 `ghVersion` 检查更新。

## 结构

| 文件 | 职责 |
| --- | --- |
| `src/main.ts` | 单个 IINA 播放窗口的音频采样、播放状态与滤镜生命周期 |
| `src/global.ts` | 选择音源、全局窗口、偏好存储、原生超时检测 |
| `src/audio.ts` | 元数据解析、噪声门、包络与频率映射 |
| `src/audio-timing.ts`、`src/audio-buffer.ts` | 按时间戳选择预读帧、提前补偿及缓冲恢复 |
